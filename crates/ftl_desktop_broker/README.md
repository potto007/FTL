# FTL desktop broker

An interactive Windows tool host for the local agent service. The default configuration grants no capture or input. Construction does not take a screenshot or send input.

The trusted host supplies `DesktopBrokerConfig` with explicit capture/input permissions, a selected monitor, verified model vision support, an approved literal loopback HTTP model endpoint, and a grant duration of at most five minutes. The model cannot create or extend these grants. The host must bind delivery of returned images to that exact endpoint and must not forward them through another provider, proxy, telemetry pipeline or persisted request log. `revoke()` stops subsequent work; `cancel_run()` invalidates a run and its observation. Before the first capture, the native broker requires its topmost, non-activating **FTL desktop control — Stop** window to start on the selected monitor. Clicking or closing it immediately revokes the shared grant. A 100 ms timer closes the window when the grant expires or is revoked; dropping the broker also revokes it. If the indicator cannot initialize, capture is denied. The window remains visible while the grant is live, including model reasoning and gaps between actions.

`tool_schemas()` returns MCP definitions for `desktop_observe`, `desktop_click`, `desktop_type`, `desktop_hotkey`, `desktop_scroll` and `desktop_release`. Capture-only grants expose observe and release. `call_for_run(run_id, name, args)` returns an MCP result containing a text metadata part and a real PNG image part. Errors never contain screenshot bytes, typed text, window titles or platform error payloads.

Coordinates use the returned image's pixel grid. Metadata includes the signed physical monitor rectangle and encoded dimensions; the broker maps pixel centers into physical desktop coordinates and rejects out-of-bounds inputs. Monitor indexes are zero-based, ordered by Windows display device name. Only the selected monitor is captured. Full-resolution capture is capped at 33,177,600 pixels, encoded output at 1,600,000 pixels / 1600-pixel longest edge / 8 MiB, and text input at 4096 UTF-8 bytes.

Each observation belongs to one run, expires after 30 seconds and is consumed before input. Another run must wait for expiry or explicit release. A Windows file handle opened without sharing at `%LOCALAPPDATA%\FTL\desktop-broker.lock` prevents concurrent FTL broker processes for the user; this conservative process lease lasts until broker drop/process exit, even after a run releases its logical lease. Focus identity, foreground bounds, display identity/geometry and last-input timestamp must match before input. A held physical key or button pauses input. Each operation checks the grant and cancellation again before dispatch, and hotkeys check between key presses. Key and button releases run on normal completion and error/unwind, with bounded retry; release failure reports uncertain state. Unicode partial dispatch compensates an unmatched final down event.

Calls intentionally have no asynchronous suspension between input-down and cleanup. The async API is compatible with tool hosts, but native capture/input performs bounded synchronous work on its calling thread. A host may offload the whole call to a dedicated worker; it must await action completion rather than drop a future halfway through an action.

Limitations: foreground checks cannot make Windows focus and input injection atomic. A user or application can change focus after the final check; this is foreground automation, with no background-window targeting or OS sandbox guarantee. An inaccessible/locked desktop fails closed. Native capture and input are not available in Session 0 or on unsupported platforms. No live desktop capture/input or real indicator window is part of unit testing. The screenshot and input backend reuses `computer_use`; its `headless` feature avoids the Windows UI timer dependency when built independently, although workspace feature unification may also include GUI dependencies. The crate does not install a Windows service, approve grants, qualify a model, or route model network requests itself. The stop control requires an interactive desktop and is not intended for an SCM service.

Validation: broker tests use fake desktop state and actors, exercising permissions, destination restrictions, negative-origin geometry, stale/focus/user-input rejection, run leases, cancellation, capture races, uncertain input, bounded arguments and balanced cleanup. `computer_use` adds signed-region tests while preserving existing non-Windows nonnegative-region validation.
